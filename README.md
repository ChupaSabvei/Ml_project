# Ml_project

## Работа вдвоём

1. Перед новой задачей обновите `main` командой `git pull --ff-only` и создайте отдельную ветку, например `git switch -c feat/baseline-model`.
2. Делите работу по файлам. Для экспериментов создавайте отдельные ноутбуки в `notebooks/`, а общий Python-код выносите в `src/`. Перед коммитом очищайте выводы и счётчики выполнения в ноутбуках. Об изменениях общих файлов договоритесь заранее.
3. Отправьте ветку на GitHub и откройте pull request в `main`. Опишите изменения, способ проверки и ожидаемый формат входных данных. Перед слиянием обновите ветку от `main`, дождитесь CI и попросите сокомандника проверить PR. Используйте Squash and merge.

## Данные и воспроизводимость

У каждого разработчика своя локальная копия данных в `data/` и своё окружение в `.venv/`. Передавайте путь к данным в скрипт аргументом или через локальную переменную окружения. Результаты обучения храните в `artifacts/` или `outputs/`. Репозиторий публичный. Перед коммитом проверяйте список изменений командой `git diff --cached --stat` и проверяйте, что в коде и ноутбуках отсутствуют приватные данные и ключи.

Для общей проверки согласуйте схему данных и параметры эксперимента в PR. Маленькие синтетические примеры можно хранить в `tests/fixtures/`. Тесты на `unittest` размещайте в `tests/`. Зависимости для проекта добавляйте в `requirements.txt` с зафиксированными версиями.
